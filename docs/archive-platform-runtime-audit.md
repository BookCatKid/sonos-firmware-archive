# Archive-platform runtime audit

Historical source audit before workflow unification, 2026-11-13. Starting HEAD: `2e3a16c`; includes the parent's in-progress frontier/publisher work. Line references describe the working tree inspected and may move during cleanup. Scope: runtime reachability, release inventories, retries, publication consistency, and all artifact families. No code/data changes, network publishing, key reads, artifact deletion, or commits were performed. This document is the only output.

## Assessment

The main problem is **multiple state machines and publication contracts**, not pervasive hardcoded version arrays. Firmware has two active discovery entrypoints and an additional model-specific archival loop. Applications and GPL maintain separate notions of “seen,” “downloaded,” “verified,” and “published.” Several paths permanently suppress retries or commit metadata before publication is established. Consolidate orchestration, identity and publishing first; preserve protocol constants, signer anchors, product identifiers and original observations.

## Prioritized correctness and hands-off hazards

### P1 — Publication and catalog changes need one transaction boundary

**Proven ordering:** the old firmware publisher writes discovery/download receipts before upload and catalog import. Auto-preserve uses `continue-on-error`, then stages whole data directories without validating the combined changes. A failed upload can therefore leave runner-local download receipts eligible for commit, distinct from a verified published receipt. [Receipt write](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_monitor_firmware.py#L212), [upload/import](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_monitor_firmware.py#L234), [tolerated failure](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/auto-preserve.yml#L128), [broad commit](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/auto-preserve.yml#L199).

A worse rollback occurs when firmware archival succeeds but subsequent raw upload fails: `git checkout -- data/catalog.json` restores checkout HEAD, discarding successful archival catalog updates as well as extraction edits. The later commit can still include the new manifest/UPD/discovery files. [Rollback](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/auto-preserve.yml#L173).

**Cleanup:** give each artifact a staged transaction: discovered → downloaded/validated → remotely reconciled → cataloged. Commit only completed publication records plus explicitly typed pending/error observations. Roll back the extraction delta, not the entire catalog. Retaining validated successful progress after another artifact fails is desirable; making runner-local receipts look published is not.

GPL has the opposite failure mode: it publishes and incrementally records successful assets, then returns nonzero on a later transient/storage failure; workflow `set -e` skips validation/commit, stranding successful new provenance on the ephemeral runner. [Incremental publication](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_gpl_direct.py#L269), [failure return](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_gpl_direct.py#L288), [workflow chain](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/archive-gpl-direct.yml#L95). Apply the same per-artifact checkpoint contract to GPL.

### P1 — Separate URL, logical package and content identities

The new frontier tracks URL candidates, but `preserve_candidates()` groups by version and downloads to `work/<version>/<filename>`. The shared downloader reuses an existing path when its size matches; it does not compare an expected content hash before reuse. Parallel candidates with the same filename can share the destination and `.part` file. If two channels serve different bytes with the same version/model filename, this loses or misattributes a variant. The older collector already collapses such URL observations by `(version, model, filename)` and chooses a URL before fetching. [Grouping](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_monitor_firmware.py#L200), [filename cache/temporary path](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/src/sonos_firmware/discovery.py#L176), [old collapse](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_monitor_firmware.py#L159), [frontier publication caller](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/discover_firmware.py#L52).

**Cleanup:** stage downloads by request identity, compute content hashes, then deduplicate bytes. Preserve all observed URL → hash associations. Keep logical version/model labels separate from immutable content identity. A filename/size cache is not a content-addressed cache.

### P1 — Google Play baseline can advance without the advertised delivery

The automatic workflow copies the entire current Google Play baseline if **any** Android archive receipt hash changes. Acquisition can return success for an already archived version and does not establish that the changed store listing's newest delivery was acquired. One package's successful recovery can therefore suppress another package's pending update. [Baseline promotion](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/auto-preserve.yml#L117), [already-known delivery exit](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_android_store_apps.py#L285).

**Cleanup:** maintain observed listing state separately from acquired delivery state, with per-package pending acquisition. Advance an acquisition checkpoint only against explicit matching version evidence; keep retrying a new listing whose delivery is not yet exposed.

### P2 — Discovery failures can appear green; app sources can disappear silently

The frontier records bootstrap errors, blocked hosts, deferred manifests and unchecked candidates. `discover_firmware.py` exits based only on preservation failures; its report does not expose a common complete/incomplete/error status. Successful downloads should still be preserved, but the run must not claim complete discovery. [Frontier result](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/src/sonos_firmware/frontier.py#L77), [exit decision](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/discover_firmware.py#L85).

Desktop discovery turns failed redirects into report rows and can return zero candidates successfully. Its checker then reports `ok` if no unknown URLs remain. Mobile discovery has a similar redirect/error path and no completeness gate. Thus a blocked source can become “no changes.” [Desktop redirects](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/discover_desktop_installers.py#L222), [desktop success](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/check_new_desktop_apps.py#L41), [mobile redirect result](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/discover_mobile_installers.py#L58), [mobile success](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/check_new_mobile_apps.py#L36).

**Cleanup:** a shared run result should distinguish complete/no-change, incomplete-with-progress, blocked and failed. Publication may consume verified progress from incomplete discovery; coverage reporting must retain the incomplete state.

### P2 — URL-only completion and permanent negatives break ongoing monitoring

Desktop unknown detection and archival completion use source-URL membership, so a changed payload at a previously recorded URL is not automatically archived. Mobile detection and archival skip all known gap URLs, including invalid/truncated prior responses. [Desktop detection](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/check_new_desktop_apps.py#L38), [desktop skip](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_desktop_installers.py#L126), [mobile gap suppression](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/check_new_mobile_apps.py#L33), [mobile skip](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_mobile_installers.py#L103).

GPL discovery skips **every previously checked version**, including failures, unless `--recheck` is supplied; sitemap discovery likewise skips previously recorded sitemaps regardless of outcome. The scheduled workflow supplies neither refresh flag. GPL archival also makes 403/404 and several invalid states manual `--retry-errors` work. This prevents both recovery from transient failures and detection of later changes in already checked sources. [Version skip](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_gpl_direct.py#L76), [sitemap skip](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/discover_gpl_sitemaps.py#L102), [archive retry selection](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_gpl_direct.py#L187), [scheduled arguments](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/archive-gpl-direct.yml#L73).

**Cleanup:** use source observations plus last-success time, content validators/hash, retry class, backoff and next-check time. Preserve negative evidence; do not make it a permanent work exclusion. For presumed immutable endpoints, state that policy explicitly and schedule integrity/revival checks.

### P2 — Publishing verification varies by path and artifact family

Keep the existing strong remote size/SHA reconciliation in the standard firmware, desktop, Android-store and GPL uploaders. Do not replace it with “upload command succeeded.” [Firmware verification](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/upload_firmware_release.py#L97), [desktop verification](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_desktop_installers.py#L174), [store signer verification](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_android_store_apps.py#L303), [GPL existing-asset verification](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_gpl_direct.py#L155).

Specific gaps:

- The legacy manual `preserve-release-assets.yml` skips an existing asset by **name only** and performs no post-upload digest reconciliation. Retire it in favor of the shared publisher. [Existing-name shortcut](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/preserve-release-assets.yml#L35).
- The official mobile publisher checks `zipfile.is_zipfile`, then reconciles the uploaded bytes. It does not apply the Android package/signer validation used by the store-delivery publisher. Byte preservation is established; APK identity/authenticity is weaker. [ZIP-only check](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_mobile_installers.py#L78), [shared store verifier](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/archive_android_store_apps.py#L51).
- Auto-preserve has no whole-change validation before commit. ConnectX/GPL validate before rebase, and GPL regenerates metadata afterward. `sonos-fw verify` validates catalog relationships, not every app/GPL receipt or remote asset. [Auto commit](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/auto-preserve.yml#L199), [GPL post-validation changes](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/.github/workflows/archive-gpl-direct.yml#L102), [validator scope](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/src/sonos_firmware/catalog.py#L82).

**Cleanup:** use one publication interface and type-specific local validators, reconcile remote bytes, then validate the final rebased metadata tree. Distinguish integrity, format validation, signer validation and source provenance in receipts.

## Runtime boundaries and cold tooling

The active dependency chain is larger than workflow filenames suggest: `check_new_*` scripts spawn discovery scripts; firmware preservation calls import/upload scripts; raw upload reuses firmware upload code; both uploaders import publication functions from `archive_web_apps.py`. `check_new_web_apps.py` dynamically imports that CLI script. This makes a web archiver a de facto shared storage library. [Firmware import](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/upload_firmware_release.py#L19), [raw imports](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/upload_raw_assets.py#L17), [dynamic web import](https://github.com/BookCatKid/sonos-firmware-archive/blob/d34f6c8/scripts/check_new_web_apps.py#L15). Move reusable storage, receipt validation and acquisition contracts into `src/sonos_firmware/`; keep scripts as thin entrypoints.

A static scan of workflow commands and literal imports/script invocations found **22 scripts without an incoming scheduled/runtime reference**. They are not thereby proven dead: documentation, tests, the CLI or human maintenance may still rely on them. Representative groups:

- Research/recovery: `diagnose_smapi_playback.py`, `find_legacy_system_word.py`, `test_legacy_flash_prefixes.py`, `generate_recovery_vault_inventory.py`, `audit_recovery_vault.py`.
- Historical/manual import and audit: `import_gpl_wayback.py`, `import_local_artifact.py`, `import_evidence.py`, `audit_missing_live.py`, `audit_missing_wayback.py`, `reconcile_gpl_release_assets.py`, `decrypt_recipient_batch.py`.
- Potentially useful missing automation: `discover_gpl_binary_references.py` and `sweep_metadata_profiles.py` are not scheduled. Their absence matters if the platform promises continual independent discovery from acquired binaries or systematic profile exploration.

Move research-only commands behind a documented maintenance boundary after checking actual users/tests. Do not indiscriminately delete them or recovered materials. This audit excludes frontend implementation changes.

## Recommended consolidation order

1. **Fix transaction rollback, receipt promotion and content identity first.** These can invalidate preservation claims even when discovery works.
2. **Make one runtime orchestrator own firmware discovery and preservation.** Retire the old `run_monitor` production route and the duplicate model-specific backfill loop; retain ConnectX's static snapshot/extraction as a type-specific adapter. Preserve existing app/GPL source adapters rather than folding every behavior into one giant script.
3. **Introduce shared job states and retry scheduling across types.** Discovery observations, pending acquisition, local validation, remote verification and publication are distinct. A provider outage must not become a no-change result or prevent committing another artifact's fully verified progress.
4. **Unify the publisher and final metadata validation.** Reuse the strong existing digest reconciliation; add format/signer validators where missing and validate after merging/rebasing generated metadata.
5. **Remove maintained release inventories from runtime inputs.** Migrate unique evidence into ordinary observations; keep protocol/product/security constants. Consolidate duplicated product/provider configuration.
6. **State capability coverage honestly.** Web, official APK, desktop, firmware and direct GPL have automatic paths. Google Play direct delivery remains configured/manual; Apple automation preserves listings, not binaries. Hands-off operation needs durable per-provider acquisition status, not a single “all apps archived” label.

This is a source-level architecture audit, not evidence that a particular remote release is currently corrupt. The identified ordering, identity and retry behaviors are established in code; their downstream losses occur under the stated failure/mutation conditions. No workflows or publication commands were executed for this audit.
